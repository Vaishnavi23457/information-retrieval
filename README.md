# Human Relevance Judgment System

> An end-to-end Information Retrieval (IR) evaluation pipeline with human relevance
> judgments, TF-IDF ranked retrieval, and automatic computation of Precision@k,
> Recall@k, MAP, and NDCG@k. Supports both a synthetic 40-document demo collection
> and the real BEIR SciFact benchmark dataset.

## Features

- **TF-IDF retrieval** with bigrams and cosine similarity ranking
- **Four-point human relevance scale** (0 Not Relevant → 3 Highly Relevant)
- **Automatic metric computation**: Precision@k, Recall@k, AP/MAP, NDCG@k
- **Two datasets**: Synthetic Demo (40 docs) and SciFact (5,183 PubMed abstracts)
- **Dataset-scoped judgments** — ratings from different collections never mix
- **Benchmark tab** — evaluate TF-IDF ranking against official SciFact qrels
- **CSV export** of judgments for offline analysis
- **49 unit tests** covering metrics, qrel matching, dataset scoping, and retrieval

Real scientific retrieval dataset from the [BEIR benchmark](https://github.com/beir-cellar/beir).

| Property | Value |
|----------|-------|
| Corpus | 5,183 PubMed abstracts |

## How to Use the App

### Search & Judge tab

1. Select a dataset in the sidebar (**Synthetic Demo** or **SciFact**).
2. Type a query in the search box and click **Search**.
3. The system retrieves the top-k documents ranked by TF-IDF cosine similarity.
4. Read each document's title and snippet, then select a relevance grade from the dropdown.
5. Click **Save Judgments & Compute Metrics**.
6. Switch to the **Dashboard** tab to see your metrics.

### Dashboard tab

- Four metric cards: Precision@k, Recall@k, AP, NDCG@k
- AP-per-query bar chart with MAP line
- Relevance grade distribution chart
- Ranked document table with grades
- CSV export button

### Benchmark tab *(SciFact only)*

- Select an official SciFact query from the dropdown.
- Click **Retrieve & Evaluate** to run the TF-IDF engine and score it against the official qrels.
- See Precision, Recall, AP, and NDCG alongside a coverage table showing which retrieved docs have qrel entries.
- A recall caveat note explains the pooling assumption for every result.

### History tab

- View all saved judgments for the active dataset.
- Download the full judgment table as CSV.
- Delete judgments for individual queries.

## Evaluation Metrics

All metrics are implemented in `evaluation.py` with no external IR library.

### Relevance threshold

| Metric group | Threshold |
|---|---|
| Precision, Recall, AP, MAP | grade ≥ 2 counts as relevant |
| NDCG | uses all four grades (0–3) as graded relevance |

---

### Precision@k

Fraction of the top-k retrieved documents that are relevant.

```
P@k = (Relevant docs in top-k) / k
```

**Example:** 4 relevant documents in the top 5 → P@5 = 4/5 = 0.80

---

### Recall@k

Fraction of all relevant documents in the judged pool that appear in the top-k.

```
Recall@k = (Relevant retrieved in top-k) / (Total relevant in judged pool)
```

**Example:** 4 retrieved out of 6 total relevant → Recall@5 = 4/6 = 0.67

> Recall is only fully accurate when all documents in the collection have been
> judged for the query. For the 40-document synthetic collection this is feasible.
> For SciFact, recall is based on the official qrel pool (see Benchmark tab note).

---

### Average Precision (AP) → MAP

AP rewards systems that rank relevant documents near the top of the list.

```
AP@k = Σ [P@i × rel(i)] / total_relevant     for i = 1..k
```

where `rel(i) = 1` if the document at rank i is relevant, else 0.

MAP is the mean of AP across all queries:

```
MAP = (1/Q) × Σ AP(q)
```

**Example:** Three queries with AP = 0.80, 0.70, 0.90 → MAP = 0.80

---

### NDCG@k (Normalized Discounted Cumulative Gain)

Measures ranking quality using graded relevance. A highly relevant document
near the top contributes more than one placed lower.

```
DCG@k  = Σ (2^rel_i − 1) / log₂(i+1)     for i = 1..k
IDCG@k = DCG of the ideal (perfect) ranking for the same grades
NDCG@k = DCG@k / IDCG@k
```

NDCG = 1.0 means the ranking is exactly ideal for the given judgments.

**Example:** Grades in retrieval order [3, 1, 2] vs ideal [3, 2, 1] → NDCG < 1.

## Benchmark Evaluation (SciFact)

The Benchmark tab compares our TF-IDF engine against the official SciFact qrels.
Key design decisions:

- **Qrel labels are kept separate from human judgments.** The 0/1 qrel labels are
  never shown as or converted into the 0–3 human grade scale.
- **Standard pooling assumption:** documents not listed in the qrels for a query are
  treated as non-relevant. A coverage table and recall note make this explicit for
  every evaluated query.
- **Binary label scaling:** qrel 1 → grade 2 inside `benchmark_evaluate()` so the
  shared metric functions work correctly. This is an internal adapter only.

## Limitations

- **Recall completeness:** Recall is accurate only when all relevant documents in
  the collection have been judged. For the synthetic dataset (40 docs) this is
  feasible. For SciFact, recall is bounded by the official qrel pool.
- **Retrieval algorithm:** TF-IDF with cosine similarity is a lexical baseline.
  It does not understand synonyms or semantic meaning. Semantic search
  (dense retrieval, embeddings) would improve ranking quality but is out of scope.
- **Judgment subjectivity:** Human relevance grades can vary between annotators.
  The system does not currently measure inter-annotator agreement.
- **Dataset size:** The synthetic collection is intentionally small for demo
  purposes. For production IR evaluation, larger standard collections
  (TREC, MS MARCO, etc.) would be more appropriate.
- **Single-user:** Judgments are stored locally in one CSV. Multi-user annotation
  and adjudication are not supported.
